# Практический тест — Бельгибаев Алихан

Практическая часть тестового задания на **Python и FastAPI**. Есть небольшая веб-страница
на HTML/CSS/JavaScript, SQLite и автоматические тесты. Теоретические ответы подготовлены отдельно.

Мой основной опыт — backend и ИИ на хакатонах, обычно использую Python/FastAPI и ИИ-инструменты
для разработки. Frontend и UX/UI пока изучаю на университетских лабораторных.
Опыта мобильной разработки нет, поэтому Flutter-задания разобраны в документации.

## Решённые задания

- **11. API задач.** Создание, получение списка и одной задачи, изменение статуса, удаление.
  Доступ только к своим задачам, постраничная выдача `limit/offset`.
  [Примеры запросов, ответов и ошибок](docs/api.md).
- **15. Форма с email и датой рождения.** Проверки на frontend и backend, сохранение в БД,
  уникальный email и ошибки рядом с полями. [Описание](docs/practical.md).
- **23. Состояния списка.** Загрузка, пустой список, ошибка, частичный результат и повтор.
  Старый ответ после смены фильтра не заменяет актуальный список. [Описание](docs/practical.md).
- **25. Flutter-экран.** Разобраны список из API, обновление свайпом, подробности,
  разделение UI и логики, отмена запроса и уход со страницы. [Решение](docs/flutter.md).
- **26. Проверки регистрации.** Unit-тесты валидации, интеграционные проверки API и БД,
  UI-тесты обязательных полей и занятого email. [Сценарии](docs/testing.md).
- **27. Скидка.** Отдельная функция с `Decimal` и тестами ниже, на и выше порога.
  Для примера: скидка 10% при сумме от 10000.00 включительно. [Границы](docs/testing.md).
- **28. Создание заказа.** Остаток и заказ меняются одной транзакцией. Проверены нехватка
  товара, откат, одновременные запросы и повтор с тем же ключом. [Сценарии](docs/testing.md).
- **29. Регрессия авторизации.** Проверки общего HTTP-контракта для web/mobile,
  неверных, истёкших и отозванных токенов, доступа к чужим данным. [План](docs/testing.md).
- **30. Flutter тест-кейсы.** Список, загрузка, ошибка, пустое состояние, поворот и возврат
  на страницу; отдельно автоматические и ручные проверки. [Тест-кейсы](docs/flutter.md).

В заданиях 25 и 30 требуется описание. Flutter-приложение здесь не создавалось,
его запуск и тестирование на устройстве не заявляются.

## Запуск

Нужен **Python 3.11+**. Из папки репозитория:

```bash
python -m venv .venv
```

Активировать окружение в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

На Linux/macOS: `source .venv/bin/activate`. Если PowerShell запрещает активацию,
используйте `.\.venv\Scripts\python.exe` вместо `python`.

```bash
python -m pip install -e ".[dev]"
python -m app.seed
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Открыть <http://127.0.0.1:8000/>. Swagger: <http://127.0.0.1:8000/docs>.

Seed создаёт искусственные аккаунты `alice@example.com` и `bob@example.com`
с учебным паролем `Demo-password-123`, товар №1 с ценой `5000.00` и остатком 5.
Повторный seed не сбрасывает данные. Можно зарегистрировать другой учебный аккаунт.
База создаётся в `data/app.db` и не попадает в Git; другой путь задаётся через `DATABASE_PATH`.

Для фиксированных версий можно использовать [uv](https://docs.astral.sh/uv/):
`uv sync --frozen --extra dev --extra ui`, затем те же команды через `uv run`.

## Тесты

```bash
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
```

Для браузерных проверок:

```bash
python -m pip install -e ".[dev,ui]"
python -m playwright install chromium
python -m pytest --ui -q
```

Тесты работают с временными БД. UI-тесты сами запускают сервер и Chromium.
Без `--ui` они пропускаются. Проверки также запускаются в GitHub Actions.

Код — в `app/`, тесты — в `tests/`, подробные ответы — в `docs/`.
Это учебный локальный сервис: SQLite, токены на 30 минут, без refresh-токенов,
восстановления пароля и подтверждения email. Токен в веб-клиенте хранится в памяти,
поэтому после перезагрузки нужен повторный вход. Реализация подготовлена с помощью ИИ-инструментов.
