# Практические решения

## 15. Форма с email и датой рождения

**Frontend** проверяет заполненность, базовый формат email, наличие реальной даты,
отсутствие даты в будущем и длину пароля. Для даты используется `input type=date`,
для email — `input type=email`. Это помогает исправить ошибку сразу.
Нельзя считать эти проверки защитой: HTTP-запрос можно отправить напрямую.

**Backend** повторяет обязательные проверки независимо от интерфейса. Pydantic
проверяет email, ISO-дату `YYYY-MM-DD`, пароль и лишние поля.
Дата рождения не может быть в будущем. В учебной форме принят диапазон с 1900 года;
это явное ограничение примера, не универсальное правило для всех продуктов.
Email очищается от пробелов по краям и приводится к нижнему регистру.
В этом сервисе адреса считаются одинаковыми без учёта регистра, включая локальную часть;
это сознательная политика аккаунтов. Нельзя повсеместно удалять точки или `+suffix`.
Проверка синтаксиса email не подтверждает владение почтовым ящиком.

**БД** хранит обязательные значения и имеет `UNIQUE COLLATE NOCASE` на email.
Проверка «сначала SELECT, потом INSERT» сама по себе не защищает от двух одновременных
регистраций: окончательная гарантия уникальности находится в БД. Пароль хранится как Argon2-хеш.
SQL-параметры передаются отдельно от текста запроса.

**Ошибки**: `422` для некорректного ввода, `409 email_taken` для занятого адреса.
Ответ содержит `fields.email`, `fields.birth_date` или `fields.password`.
Интерфейс показывает сообщение под соответствующим полем, устанавливает `aria-invalid`,
переводит фокус к первому ошибочному полю и сохраняет уже введённые данные.
При успехе пароль очищается. Ошибка сети отображается отдельно, кнопку можно нажать повторно.
В ответе сервера нет исходного значения пароля или внутренних ошибок БД.

## 23. Состояния списка

| Состояние | Что видит пользователь | Следующее действие |
|---|---|---|
| Первая загрузка | «Загрузка…», контейнер `aria-busy=true` | Дождаться или сменить фильтр |
| Успех | Задачи текущего фильтра | Открыть подробности, изменить статус, удалить |
| Пустой результат | «Задач пока нет», предложение добавить или сменить фильтр | Добавить задачу / выбрать другой статус |
| Ошибка первой страницы | Сообщение, кнопка «Повторить» | Повторить текущий запрос |
| Частичный результат | Уже полученные задачи и предупреждение об ошибке следующей страницы | Повторить загрузку недостающей страницы |
| Повтор | Индикатор загрузки; прежняя часть списка остаётся при повторе следующей страницы | Получить недостающие данные |

В реализации **partial** означает успешную первую страницу и ошибку следующей,
а не смешивание записей из разных фильтров. API сам возвращает целую страницу атомарно.
При смене фильтра старые строки убираются, чтобы они не выглядели как новый результат.

В `TaskList` хранится состояние и выполняются запросы; `render` занимается DOM.
Каждый новый запрос отменяет предыдущий через `AbortController` и получает свой
номер поколения. Перед применением результата контроллер сравнивает его с текущим.
Поэтому ответ старого запроса не может заменить результат нового, даже если отмена
произошла слишком поздно. Проверка нужна также для ошибок и `finally`, чтобы старый
запрос не сбросил индикатор новой загрузки.

Запрос списка ограничен 10 секундами. Повтор первой страницы запускает её заново;
повтор следующей использует прежний offset и дописывает результат один раз.
При уходе со страницы и выходе из аккаунта активный запрос отменяется, поколение
увеличивается. Содержимое задач выводится через `textContent`, чтобы название не
выполнялось как HTML.

Браузерные проверки: `test_ui_network_error_and_retry`,
`test_ui_partial_result_keeps_first_page`,
`test_ui_loading_and_fast_filter_change_ignore_old_response`.
